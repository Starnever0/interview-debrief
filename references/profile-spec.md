# 个人面试档案：`~/.interview-profile/`

读档案或写档案前读本文件。

## 一、为什么要独立目录

档案是"用户这个人"的信息（简历、技术栈、历次面试表现），**跨项目、跨 agent 都要能用**，所以不能放在某个工作目录里，也不能放在 skill 目录内（skill 更新会被覆盖）。统一放在**家目录下的固定目录**——`~` 在 Windows / macOS / Linux 上都成立，天然平台中立。但是具体路径要告知用户。

## 二、目录形态

```
~/.interview-profile/
├── candidate-profile.md      # 候选人档案（按模板填写，含转录关键词清单）
├── resume.md                 # 简历（解析后沉淀，或按模板手填）
├── 索引.md                   # 历次复盘的索引与跨场统计
└── 面试复盘/                 # 历次单场复盘档案
    ├── 2026-10-11-A公司-Agent开发-一面.md
    └── 2026-09-28-B公司-Agent开发-二面.md
```

**不是所有文件都必需。** 只有 `candidate-profile.md` 或 `resume.md` 之一存在时，就已经能提供背景增益；两个都没有也不影响复盘。

`candidate-profile.md` 按**四块**组织（模板见 `assets/candidate-profile-template.md`），对应"哪些东西值得跨场次沉淀"：

| 块              | 装什么                                                 | 为什么                     |
| -------------- | --------------------------------------------------- | ----------------------- |
| **一、个人介绍**     | 一句话定位 / 教育背景 / 求职方向 / 目标岗位 / 身份 / 常驻城市 / 技术栈 + 一段**可直接口述的自我介绍** | 让复盘知道"你是什么背景的人"，并让答法贴合你 |
| **二、转录关键词清单**  | 只收**专名**（项目名 / 小众技术 / 背景领域名）                        | 转写纠错；口径见第四节             |
| **三、项目经历**     | **自然段叙述**：背景 / 目标 / 遇到的问题 / 方案 / 结果（可直接粘简历原文） | 项目题占面经大头，也是个性化答法与转写还原的前提 |
| **四、其他跨场复用信息** | 技术深度自评 / 常被追问的薄弱点 / 求职动机与规划 / 其他（论文、获奖、作品链接）        | 剩下的通用素材                 |

**判断某条信息该不该进档案**：跨场次还成立吗？成立 → 进；只对某一场面试成立（公司、岗位、面试官、当次结果）→ 进 `索引.md` 或单场档案。

## 三、读取（流程第 0 步，在清洗之前）

**这一步放在语境还原之前**——档案里的转录关键词清单能直接提高转写纠错的准确率，读晚就没用了。

1. **目录不存在** → **先看材料本身，条件触发**：
   - **材料疑似转写稿**（明显错字、无标点、说话人混淆、口语碎片、术语写错）→ **询问一句**是否愿意先建一份档案（说明：有了它，转写稿的纠错会更准，"更好的答法"也能贴合你本人的项目）。
     - 用户同意 → **停止本场流程**，按第四节引导建立档案（复制模板填写，或直接传简历文件解析）；完成后等用户下一轮再触发。
     - 用户拒绝 → 正常继续，**不阻塞**；同一会话内不再重复问。
   - **材料本身就干净**（面经文字、面经截图一类，清洗不难）→ **不问，直接继续**——这类材料用不上关键词清单，问也徒增摩擦。
   - 用户明确表示"以后别问"时，之后不再主动问。
2. **目录存在** → 按序读取：
   - `candidate-profile.md`（优先，最具体）——特别关注其中的**转录关键词清单**，下一步语境还原时用它把误听词还原成正确写法；
   - `resume.md`（补充）；
   - `索引.md`（若有）——用于跨场对照：本场出现的问题若在历史中已有记录，在报告里注明"**第 N 次出现**"并列出前几次发生在哪一场。

档案作为背景注入，用于三件事：更准确地剖析意图（知道用户的技术栈与项目）、更贴合地给"更好的答法"（用他自己的项目做例子）、**更准地还原转写**（靠关键词清单对齐专有名词）。

**顺手体检**：读到 `candidate-profile.md` 时，若关键词清单里出现明显不该收的东西——**通用技术词**（RAG、Harness、Token…）或**某次面试的公司名**——在本轮结束时**顺口提一句**，问是否清掉，不擅自改用户档案。这与第四节的收录规则是同一套标准。

## 四、沉淀（流程第 8 步，复盘结束后询问一次）

**只在用户同意后执行，且只问一次。**

1. 把本场复盘文档写入 `~/.interview-profile/面试复盘/`（文件名同 `doc-template.md` 的命名规则）。
2. 更新 `索引.md`（见第五节）。
3. 若 `candidate-profile.md` / `resume.md` 都还不存在：
   - 询问用户是否愿意建立档案；
   - 愿意 → 二选一：① 把 `assets/candidate-profile-template.md` 复制到 `~/.interview-profile/candidate-profile.md` 让用户填；② 用户直接传简历文件（PDF / Word），解析后沉淀为 `resume.md`。
   - 不愿意 → 跳过，不再追问。

**首次写出档案时**，用一句话说明："这些文件存在 `~/.interview-profile/`，下次复盘会自动读取，能看出反复出现的问题。" 不展开解释机制。

### 写 `candidate-profile.md` 的纪律（关键）

这份文件**跨会话长期保留**，只装"关于用户本人、不会过时"的信息。两件事最容易写错：

1. **不要把当次面试的信息写进去。** 本场的公司 / 岗位 / 面试官 / 结果属于**单场信息**，只进 `索引.md` 与单场档案（公司用代号），**不进 `candidate-profile.md`**。跨会话档案里出现某个面试公司的名字，是典型的串场污染。
2. **转录关键词只收专名。** 收这三类：**项目 / 产品 / 系统名称**、**小众技术 / 自研框架 / 内部术语**（不完整多模态融合）、**具体的背景 / 领域名称**（自动驾驶关键安全场景生成）。**不收**：
   - 通用技术词与格式名 / 行话（RAG、Transformer、Agent、Harness、微服务、一致性哈希、W8A8、dogfood…）——模型自己认得出来，写进去只是噪音；
   - 面试官姓名与任何联系方式（**用户本人的联系方式也不必写**，复盘用不上）；
   - 本次面试的公司 / 岗位 / 结果（单场信息，见上一条）。
   - 用户新增关键词时若给的是通用词，**提醒一句**"这类模型能自己认出来，收进来意义不大"，而不是照单写入。

判断标准一句话：**这个词，模型靠常识猜不出来、只有用户本人会说——才值得收**。

**边界：公开产品名要不要收？—— 收。** 判据不是"这个东西是否公开"，而是"**转写稿里它会不会被听错、模型靠上下文能不能自己还原回来**"。`SGLang` 会被写成 "sg量"、`魔搭` 会被写成 "摩达"、`昇腾` 会被写成 "升腾"、`Scenic` 会被写成 "塞尼克"——这类词留着才真正有纠错价值。真正不收的是**技术概念词 / 格式名**（`RAG`、`Harness`、`W8A8`、`dogfood`）：它们本来就不太会在转写里被听成另一个词，而且模型凭上下文就能还原。

## 五、索引.md 结构

```markdown
# 我的面试档案

最近更新：<日期> ｜ 已复盘 <N> 场

## 场次记录

| 日期 | 公司 | 岗位 | 轮次 | 结果 |
|------|------|------|------|------|
| 09-28 | B公司 | Agent 开发 | 二面 | 已挂 |
| 10-11 | A公司 | Agent 开发 | 一面 | 待定 |

## 重复出现的问题（按分类统计）

| 分类 | 次数 | 出现场次 |
|------|------|---------|
| 计算机基础八股 | 2 | 09-28, 10-11 |

**需要注意的不一致：**
（同一问题在不同场次的说法有出入时列出，如离职原因、职级、项目归属。）

## 待补强清单

- [ ] 补齐分布式一致性基础
- [x] 项目贡献归属讲清楚（10-11 已改善）
```

维护规则：

1. **样本不足要写明**：同一分类少于 3 场时写"样本不足，暂不归纳"，不从两场里总结规律。
2. **说法不一致单独列出**：跨场归档才能发现的、单场看不到的部分。
3. **已完成项打勾保留，不删除**。
4. 频次统计以各场档案的分类字段为准，不重新通读正文。

## 六、跨场分析

**归档满 3 场后主动提示一次**是否做跨场分析（之后不再主动问）：

> ~~已经存了 3 场，要不要一起看看反复出现的问题？~~

~~跨场分析输出三部分：~~

1. **~~按分类~~**~~：哪类问题出现最多、有没有随场次减少。~~
2. **~~按趋势~~**~~：同一类问题的表现是改善还是原地踏步。~~
3. **优先级建议**：重复最多的前三项，作为下次面试前的准备重点。

## 七、隐私

- **公司用代号**（A公司 / B公司），同一公司前后代号必须一致。
- **不保留面试官真实姓名、联系方式**；材料里出现时，提示用户可用代号替代，归档同样用代号。
- 涉及企业非公开信息时，提醒用户自行判断是否适合写入档案。
