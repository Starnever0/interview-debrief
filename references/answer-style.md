# 写作规范：意图剖析 / 评价 / 更好的答法

写内容前必读。这份规范决定复盘文档「有没有价值」还是「看起来很懂其实在编」。

---

## 一、面试官意图剖析：一句核心意图，需要时补一句

**默认只写一句核心意图就够了；确实还有值得说的另一种可能时，再补一句额外意图。**不要为了凑"三层"把一句话拆成三行——那只会挤占版面，把问题和回答隔得更远。

| 部分 | 写什么 | 要求 |
|---|---|---|
| **核心意图**（必给） | 他大概想确认什么 | 用"可能""倾向于""像是在"，不用"一定""说明""就是"；判断有依据时，把关键观察（原句、追问次数）顺手揉进这句话 |
| **额外意图**（可选） | 另一种解释 / 需要留意的点 | **只在真有意义时写**；没有就留空，不硬凑 |

**示例（好）**

```
核心意图：连续追问了三次召回口径，可能是在确认这件事是不是他本人主导的，顺带看有没有量化归因的方法。
额外意图：也可能该团队正踩同样的坑，想借你的经验。
```

**示例（坏）**

```
面试官反复追问，说明他不相信这个项目是你做的，你的回答没有说服他。
```

坏在：把推断说成事实（"说明"），且把人给判了。

**两条禁忌**

1. 不用断言式措辞：`说明` / `就是` / `一定` / `肯定` / `显然`。
2. 不用通例覆盖本场材料。经验里的"这类岗位通常会被追问数据口径"，如果本场根本没出现数据题，那就是没出现，不要写成"应该被问却没问到所以有问题"。

**背景来源的优先级**（影响核心意图的准确度）：

1. **材料内文**——面试官开场自我介绍、面试中提到的业务、反问环节透露的信息。这是最可靠的一手背景。
2. **公司名联网检索**——材料里出现了公司名时，可选地检索公开背景（业务线、技术栈、近期动向）作为参照，并标注"外部信息，供参考"。**不阻塞**：搜不到就往下走。
3. **通用行业推断**——公司不明（匿名面经很常见）时退化为通用意图，并显式写明"无法确认公司背景，以下为通用推断"。

**题目不涉及公司就不强行结合**。若整场只问项目和八股、没有结合公司背景或场景题，就按通用意图分析，不要为了显得懂背景而硬扯。

## 二、评价：四要素 + 一个轻量标记

**仅当该题有回答时才写。面经类材料只有问题没有回答，一律不评价。**

| 项 | 写什么 |
|---|---|
| **标记** | `命中` / `部分命中` / `偏离`。只用于快速定位，不做精确打分 |
| **踩中考点** | 回答里对的地方 |
| **遗漏** | 该覆盖却没覆盖的要点 |
| **表达与结构** | 结构、冗余、口头禅、逻辑跳跃、时长 |
| **最该改的一处** | 只挑最关键的一处，不罗列一堆 |

**内容与表达分开写。**同一段回答可能内容成立但表达不合对方的习惯，也可能反过来。两件事分别记录、分别给建议，不要合成一个结论。

例：社招候选人在国企场次说"这个项目我主导的"——内容层面这是清晰的个人贡献陈述，没有问题；表达层面这个说法在该场景下可能影响观感。两句都要写，不要因为后者就把前者判为失误。

## 三、更好的答法：三层

**每题都给**（这是本技能相对"面试官视角诊断"类工具的核心差异）。

### 第 1 层：方向（必给）
一句话说清"这题面试官想听什么"。例：*想听你如何度量并归因召回问题，而不是用了什么组件。*

### 第 2 层：要点骨架（必给）
该覆盖的 bullet 清单，作为答题的检查表。

### 第 3 层：示范回答（可选，谨慎给）

分两类处理，**这条边界不能糊**：

| 题型 | 给法 |
|---|---|
| **有公认标准答案**：八股、概念定义、算法、协议流程… | 可以给一段**完整示范回答** |
| **场景题 / 开放题 / 行为题** | **只给方向与加分项**，并标注"参考方向，非唯一答案"，不硬塞标准答案 |

### 硬约束：个人经历类的题

涉及**用户个人经历**的题（"讲讲你那个项目"），示范回答**只能用用户亲口说过的素材重组**：

- 可以把他说得零散的内容讲得更有条理；
- **不能添加没发生过的内容**，包括项目、数字、职责；
- 缺失的事实标 `【需核实：×××】`，交回用户去核实。

用户要求"帮我说得好听点"时，同上处理：可以重组与润色，但不添加。

---

## 四、忠实性

- **有客观正解的题**（八股 / 算法 / 协议），若模型不确定，标注"待核实"，宁可留白也不编。
- **允许联网核实、但不阻塞**：能搜到权威说法就用于增强（尤其八股类），搜不到就用模型知识并在文档中标注不确定。检索到的外部信息标"外部信息，供参考"。
- **不预测结果**：不给通过概率、不给百分比、不写"你大概率能过"。用户直接问"我过了吗"时，列出本场明确的加分项与明确的问号，说明结果还取决于材料中观察不到的因素（名额、内推、同期竞争者、预算、面试官偏好），把判断权交回用户。

---

## 五、语气

- 对用户：直接、务实，不安慰也不打击。诊断本身不放水；情绪低落时可以先给一段初步观察让用户看到价值，再继续。
- 不用营销词与鸡汤（"太棒了""你离 offer 只差一步"）。
- 中文书写；英文面场次可保留英文原句，但诊断用中文。
