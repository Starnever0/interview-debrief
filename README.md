# interview-debrief

> 把一次面试的材料（转写文本 / 面经文字 / 面经截图），整理成一份**候选人视角**的复盘文档 —— 这轮在考什么、面试官每道题可能想确认什么、自己答得如何、**怎样答更好**。

一个遵循 **SKILL.md** 约定的通用 Agent Skill，把「**丢一份面试材料 → 还原成语句清晰的面试记录 →（你确认无误）→ 出复盘文档 + 作答方向**」这条流程固化下来，让每次复盘都站在同一套标准上。

**不绑定任何特定 Agent**：任何支持该约定的 agent 都可以直接加载使用。

---

## 效果预览

**输入** —— 一段转写文本、一份面经文字，或几张面经截图：

```
帮我复盘这次面试
（附：面试转写.txt / 面经截图 1.png、2.png、3.png）
```

**输出** —— 一份复盘文档，结构固定：材料与背景 / 本轮考察脉络 / 反问环节情报 / 整体表现评价（可选）/ 逐题清单 / 汇总统计。

完整成品见 [`assets/sample/sample-review.md`](assets/sample/sample-review.md)。逐题块的形态大致是：

```markdown
### Q1. 你们 RAG 的召回质量是怎么保证的？

**分类**：项目经历 / RAG 召回
**面试官意图**：连续追问三次召回口径，可能是在确认这件事是不是他本人做过。
补充：也可能只是固定题本里的追问。
**我的回答**：讲了用 rerank 提效果，召回率大概提升百分之三十左右。
**评价**（部分命中）：踩中考点……｜遗漏……｜最该改的一处……
**更好的答法**：方向 → 要点骨架 →（仅当有公认标准答案时）示范回答
```

## 它解决什么问题

面试复盘的通病，几乎都出在**材料**和**视角**上：

| 通病 | 后果 | 这个 skill 的做法 |
| --- | --- | --- |
| **转写稿满是错字** | "一致性哈希"被转成"一次性哈希"，照着错题复习，整题方向都歪 | 先做**语境还原**，再强制走一次**复核对齐关卡**（见下） |
| **面经只有题、没有答** | 想评价却无从评价，只能硬编 | **评价是条件性的**：没回答就不评价，只给意图 + 作答方向 |
| **就题论题** | 不看公司与岗位背景，猜不到面试官真正想确认什么 | 先扒材料内文（开场白 / 反问环节提到的业务），有公司名再**可选**联网补背景 |
| **复盘完就丢** | 每次从零开始，看不出自己反复踩的坑 | 可选沉淀到 `~/.interview-profile/`，跨场次对照 |

它与"面试官视角诊断"类工具的关键差异：**本 skill 会给参考答案 / 作答方向** —— 这是它的核心价值，不会为了"客观"而省略。

## 核心设计

**① 复核对齐关卡（唯一阻塞环节）**

材料还原完先停下来，把 **还原稿全文** + **问题 ↔ 回答对照表**交给你确认：改错字、补背景、对齐被粘错的回答。理由很实在 —— 转写错一次，后面整套分析全白做。改完还会**回读核对**，防止"改了但没保存"。

**② 面试官意图是"一句推断"，不是三段套话**

写一句有实质判断的核心意图（可结合公司与岗位背景），确有第二种可能时再补一句。明确区分**事实**与**推断**，禁词 `说明 / 就是 / 一定 / 肯定 / 显然`。

**③ 评价与答法都有硬约束**

- 评价**仅有回答时才做**（定性短评 + 命中 / 部分命中 / 偏离）；
- 更好的答法分三层：方向 → 要点骨架 → 示范回答，其中**示范回答只在有公认标准答案时给**（八股 / 算法 / 概念题），场景题只给方向与加分项；
- **涉及个人经历的题，示范回答只能用你说过的事实重组**，不得编造项目、数字、职责，缺失事实标 `【需核实：×××】`。

**④ 门禁脚本，机器守铁律**

出文档前先跑校验：结构是否齐全、有没有"没回答却给了评价"、有没有"给了示范回答却不属于标准答案题"、题干在确认后的记录里找不找得到（抓改写与漏题）。**error 直接拒绝渲染**，warning 只提示。

**⑤ 个人档案：可选，但会让下一次更准**

`~/.interview-profile/` 里可以放你的简历与项目背景。其中「**转录关键词清单**」（项目代号、小众产品名、领域名）专门用来纠正转写错字 —— `SGLang` 会被写成 "sg量"、`魔搭` 会被写成 "摩达"。有则启动即读，没有也不影响。

## 适用场景

✅ 适合

- 面试转写文本 / 面经文字 / 面经截图 → 复盘、整理、分析
- 想知道"这道题面试官到底想听什么、我该怎么答"
- 想把历次面试沉淀下来，看出反复出现的问题

❌ 不适合

- **音频转录**（本 skill 不做 ASR，请先用你自己的工具把录音转成文字）
- 群面 / 无领导小组讨论复盘
- 预测面试结果（本 skill **不给通过概率**）

触发词：面试复盘、面经整理、复盘这场面试、把这份面经整理一下、面试记录分析、复盘我这轮面试。

## 安装

本 skill 遵循通用的 `SKILL.md` 约定，安装方式就是**把它放进你所使用 agent 的 skills 目录**（目录名保持 `interview-debrief`）：

```bash
git clone https://github.com/Starnever0/interview-debrief.git <你的-skills-目录>/interview-debrief
```

常见 agent 的 skills 目录示例：

| Agent | 用户级目录 |
| --- | --- |
| Claude Code / Anthropic Agent Skills | `~/.claude/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` |
| 其他 | 你所使用 agent 对应的 skills 目录 |

若你的 agent 不使用 skills 目录，也可以直接把 `SKILL.md` 连同 `references/` 下三个文件一起交给它，功能一致，只是需要手动附加。

## 使用

直接用自然语言触发即可，材料通过对话发送：

```
帮我复盘这次面试
```

```
这是某公司 Agent 开发一面的面经，整理成复盘文档
```

**流程**（8 步）：

```
① 校验材料（没收到就提示你补发）
② 读个人档案（可选）
③ 取数：文本 → 语境还原；图片 → 模型视觉提取 → 语境还原
④ 复核关卡：还原稿 + 问答对照表交你确认（阻塞）
⑤ 确认回读：核对改动是否真的落盘
⑥ 剖析面试官意图（逐题 + 本轮考察脉络）
⑦ 评价（仅有回答时）+ 更好的答法
⑧ 分类 → 落盘复盘文档 →（可选）询问是否沉淀档案
```

**依赖**：脚本只用 Python 标准库，Python 3 即可，无第三方依赖。

## 产出

每场复盘产出三个文件（默认落在当前目录的 `面试复盘/`）：

| 文件 | 内容 |
| --- | --- |
| `<日期>-<公司>-<岗位>-<轮次>.md` | 复盘文档（主交付物） |
| `<基名>.json` | 结构化数据（可重渲染、可机器统计） |
| `<基名>.记录.md` | 你确认后的面试记录（可追溯） |

文件名里缺失的段会自动省略；目标文件已存在时脚本**默认拒绝覆盖**，确认重跑需加 `--force`。

## 边界与隐私

- **不转录音频、不做 OCR 脚本**：图片文字由模型视觉提取；音频请先自行转文字。
- **不预测结果**：不给通过概率、不给百分比。
- **隐私**：公司名建议用代号（A公司 / B公司），不写入面试官真实姓名与联系方式；涉及企业非公开信息时请自行判断是否适合写入档案。
- **意图是推断**：所有关于"面试官想考什么"的判断都是合理推断，不是事实；文档里会明确标注。
- 不提供法律意见；涉及劳动合同、竞业限制、录音合法性等，请咨询专业人士。

## 说明

- 个人数据统一放在家目录 `~/.interview-profile/`（跨 agent 通用，不随 skill 更新被覆盖）。
- 具体产品、技术细节请以官方最新资料为准；本 skill 对不确定的参考答案会标注"待核实"，宁可留白也不编。
